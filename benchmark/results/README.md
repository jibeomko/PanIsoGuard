# Committed benchmark results

PanIsoGuard's accuracy claims must not live only in prose. This directory is the
**git-tracked home for every benchmark metric**, so a reviewer can read the numbers
(and how they were produced) without assembling 4–5 bioinformatics conda
environments, and CI can detect when a change moves them.

## Layout

```text
benchmark/results/
├── README.md                      # this contract
├── schema.json                    # JSON Schema for every <protocol>/metrics.json
├── MANIFEST.tsv                   # index of committed artifacts + provenance + status
├── collect.py                     # regenerate self-contained metrics + validate / --check drift
├── controlled_truth/metrics.json  # status=tracked     (regenerated by collect.py)
├── synthetic_axes/metrics.json    # status=tracked     (regenerated by collect.py)
└── sqanti_sim/
    ├── metrics.json               # status=transcribed_pending_tracked_run
    └── sweep.tsv                  # the AUPRC threshold-sweep table (release blocker)
```

Only small artifacts are tracked (`metrics.json`, `sweep.tsv`, `MANIFEST.tsv`); the
bulky regenerated intermediates (FASTA/GTF/BAM/SAM) are `.gitignore`d.

## Result envelope (`schema.json`)

Each `<protocol>/metrics.json` is one envelope: `protocol`, `scope`, `status`,
`tool_version`, `ruleset_version`, `generated_utc`, `data_provenance`, `command`,
`source`, `metrics` (protocol-specific), `notes`. `status` is one of:

| status | meaning |
|--------|---------|
| `tracked` | self-contained; `collect.py` regenerates it from the built binary and **drift-checks** it. Reproducible byte-for-byte (modulo timestamp). |
| `transcribed_pending_tracked_run` | number copied from `docs/validation.md`; the protocol needs heavy external tooling, so it is **not yet** regenerated here. `source` records where it came from. |
| `pending` | not yet produced. |

## Regenerating

```bash
cmake --build build -j
python3 benchmark/results/collect.py            # rewrite the tracked metrics.json
python3 benchmark/results/collect.py --check     # CI mode: non-zero on drift / schema error
```

`collect.py` runs each self-contained protocol's `ci_check.py --emit-metrics`, wraps
the output in the envelope, and (in write mode) preserves `generated_utc` when the
numbers are unchanged so re-running produces no noisy diff. The same drivers are the
CTest integration tests (`integration_controlled_truth`, `integration_synthetic_axes`),
so a tracked metric and its pass/fail assertion share one code path.

## The SQANTI-SIM AUPRC sweep (release blocker)

`sqanti_sim/sweep.tsv` is the template for the **threshold sweep** called out in
`docs/validation.md` ("Calibration caveat"): one row per `config/rules.default.toml`
threshold configuration, with its AUPRC and operating-point precision/specificity.
Today it holds a single seed row — the shipped `default-0.0.1` config, transcribed
from the published AUPRC 0.970. The sweep is **automated** by
[`benchmark/sqanti_sim/sweep.py`](../sqanti_sim/sweep.py): the expensive half is
producing the truth set once (`run.sh`); given those artifacts the harness re-runs
`adjudicate` across the threshold grid, scores each config with `score.py`, writes
every row to `sweep.tsv`, and (with `--emit-metrics`) writes the tracked
`metrics.json` from the operating point. To close the gate:

```bash
bash benchmark/sqanti_sim/run.sh                       # heavy: build the truth set once
python3 benchmark/sqanti_sim/sweep.py "$PIG" \
    --work benchmark/sqanti_sim/work --full \
    --scope gencode_vNN_chr22 \
    --emit-metrics benchmark/results/sqanti_sim/metrics.json
python3 benchmark/results/collect.py --check           # confirm schema-valid
```

That flips `sqanti_sim` to `status=tracked`. Until then it stays
`transcribed_pending_tracked_run` and the thresholds remain conservative defaults,
**not** swept/tuned. The heavy protocols `end2end` and `hg002` carry the same
transcribed-pending envelope (with a `command` to reproduce) and become `tracked`
the same way.

## Adding a protocol

- Self-contained (python + the binary only): give it a `ci_check.py --emit-metrics`
  driver and add it to `SELF_CONTAINED` in `collect.py`.
- Heavy (needs callers/simulators): hand-commit a schema-valid `metrics.json` with
  `status=transcribed_pending_tracked_run` and a `command` that reproduces it, and
  list it in `MANIFEST.tsv`.
